---
title: Doors and universe
description: Restrict crawls by domain and path. Links outside the domain scope are doors.
---

## Universe

Universe = eTLD+1 of the seed URL ∪ `allowed_domains` (each an eTLD+1 host, max 20). The crawler follows in-universe `http(s)` links that match the path scope. Hash-only, `mailto:`, and `javascript:` links are dropped.

To include `docs.example.com` and `blog.example.net` from a seed on `www.example.com`, pass `"allowed_domains": ["example.net"]`. `example.com` is already in universe from the seed.

Invalid allowlist values return **400** `invalid_domain`.

## Path scope

Set **Allowed path prefixes** in the [crawl console](https://crawlapp.lumen-labs.ai/app/crawls/), or send `allowed_path_prefixes` when you [create a crawl](/v2/create-and-poll#create).

- `/docs` matches `/docs` and descendants such as `/docs/install`. It excludes `/docsite` and `/Docs`.
- Multiple prefixes use OR matching. For example, `["/docs", "/guides"]` includes either section on any in-universe host.
- Matching uses the case-sensitive URL pathname. Query strings and fragments do not affect the match. Supply paths beginning with `/` and omit the host, query, and fragment. Trailing slashes on prefixes are ignored.
- The seed URL must match one prefix when the list is nonempty. A mismatch returns **400** `invalid_url`.
- Discovered links, sitemap page entries, and page redirects must stay in scope. The crawler skips same-universe links outside the allowed paths. If a page redirects outside scope, the crawl records a failed fetch with `crawl_scope_blocked`.

Leave the field blank or omit it to use domain-based scope alone.

## Doors

An off-universe `http(s)` link is a **door**. The crawler records `url`, `host`, `source_url`, and a hit `count`. It never fetches the door.

```bash
curl https://crawler.lumen-labs.ai/v1/crawls/$ID/doors \
  -H "Authorization: Bearer $LUMEN_CRAWLER_KEY"
```

Door records have no Markdown and no cleaned JSON. `next_cursor` is currently always `null`.

## follow_doors

`follow_doors: true` returns **422** `follow_doors_unsupported`. To enter a door host, start a **new** crawl with that URL as the seed (and add it to `allowed_domains` on a parent site if you want both in one universe).

<AgentNote>

Never treat doors as crawled pages. If the user needs another host, POST a new crawl. Do not set `follow_doors` to true.

</AgentNote>
